# Palate Release Notes: v1.5.24

**Release Date:** September 5, 2026  
**Target Version:** `1.5.24`

## Highlights

Palate v1.5.24 hardens the Whatbox-hosted PostgreSQL boundary and adds authenticated encryption for Sage conversation history.

## Database access hardening

- Moved the application database connection from loopback TCP to the local PostgreSQL Unix socket.
- Replaced trusted local authentication with operating-system identity verification (`peer`).
- Explicitly rejects IPv4 and IPv6 loopback TCP database connections.
- Restricted `.env` and `.env.local` to owner-only permissions (`0600`).
- Preserved application availability while removing the previous passwordless database-superuser path available to other local Unix accounts.

## Sage history encryption

- Encrypts chat-session titles, message bodies, and preserved model reasoning before Prisma writes them.
- Uses AES-256-GCM with a fresh random 96-bit IV for every field write.
- Derives purpose-specific keys with HMAC-SHA-256 from `PALATE_ENCRYPTION_SECRET`.
- Binds ciphertext to its field purpose with authenticated additional data, preventing valid ciphertext from being moved between title, content, and reasoning fields.
- Uses a versioned `enc:field:v1` envelope with strict malformed-data and tamper detection.
- Keeps decryption inside server-only code and returns plaintext only after authenticated, user-scoped application reads.

## Safe migration and administration

- Added aggregate-only inspection, dry-run, and confirmed live migration commands for Sage chat encryption.
- Uses in-memory round-trip verification and compare-and-swap updates before committing each migrated record.
- Migrated 7 existing chat titles, 18 message bodies, and 8 stored reasoning blocks with no corrupt records, write conflicts, or errors.
- Verified the existing Gemini key and all three Google OAuth account records remain encrypted and readable.
- Created and test-opened an encrypted pre-migration rollback dump without logging plaintext or secrets.

## Verification

- New encryption tests cover Unicode and empty values, idempotency, field-purpose separation, tamper detection, malformed envelopes, and controlled legacy reads.
- Focused encryption and OAuth-state verification passed: 11 tests.
- TypeScript completed with no errors.
- The isolated Next.js 16 production build completed successfully.
- The full suite completed with 388 passing and 24 integration tests skipped by configuration. One existing OAuth-state test remains nondeterministic only during the parallel full-suite run and passes when isolated.
- Post-deployment checks confirmed HTTP 200, socket peer authentication, rejected loopback TCP, fully readable encrypted records, and no protected-field errors in the production log.

## Operational boundary

Whatbox stores hosted files as cleartext at the server layer, so this release uses application-level encryption for high-risk fields rather than placing PostgreSQL on a FUSE-backed encrypted directory. Strong off-host backups still require recipient-key encryption whose private key never resides on Whatbox.
