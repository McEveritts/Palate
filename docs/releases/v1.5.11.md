# Palate Release Notes: v1.5.11

**Release Date:** September 3, 2026  
**Target Version:** `1.5.11`

---

## Highlights

Palate v1.5.11 is a comprehensive security remediation and hardening release delivering self-hosted Jellyfin authentication exclusivity, atomic Google Calendar integration controls, real PostgreSQL test verification, and strict cryptographic key separation across independent functional boundaries.

---

## 1. Atomic Google Account Ownership & Linking
- **Race-Proof Account Linking**: `Account` records are linked inside atomic database transactions (`prisma.$transaction`). Check-then-act races are eliminated: an existing linked Google account cannot be hijacked or reassigned to a different Palate user.
- **P2002 Concurrency Recovery**: Handled unique constraint collisions on `provider_providerAccountId` gracefully by verifying winning ownership and falling back to token refresh without failing or corrupting state.
- **Single Connection Invariant**: Enforced that a Palate user can have at most one Google Calendar integration record.

## 2. Hardened OAuth State & PKCE Handshake
- **Authenticated Encryption**: OAuth state parameter and cookies use AES-256-GCM authenticated encryption (`enc:state:v1:...`) with HMAC-derived domain-separated keys.
- **Strict Schema Validation**: Returned state payloads undergo strict runtime schema validation verifying matching state, code verifier, user ID, issuance timestamp, and expiration.
- **Terminal Cookie Clearance**: The temporary state cookie is purged on every terminal callback outcome (success, denial, error, or expiration).
- **Bounded HTTP Timeouts**: OAuth token exchange and userinfo requests enforce 10-second request timeouts via `AbortController`.

## 3. Minimized Google Identity Footprint
- **Authenticated Userinfo**: User identity (`sub`) is resolved directly from Google's authenticated userinfo endpoint (`https://openidconnect.googleapis.com/v1/userinfo`) using the exchanged access token, rather than unverified JWT parsing.
- **No Token Bloat**: Raw `id_token` payloads are stripped before persisting to the database.
- **Scope Verification**: Scopes are minimized to `openid` and `https://www.googleapis.com/auth/calendar`. The callback verifies the granted scope string explicitly contains calendar authorization.
- **Sanitized Logging**: Token exchange bodies, userinfo payloads, and credentials are never logged.

## 4. Optional Connected Calendar Integration
- **Sync Defaults to OFF**: New Google Calendar connections initialize with `googleCalendarSyncEnabled: false`. Sync must be explicitly toggled on by the user.
- **Connection Health Checks**: Settings API verifies decryptability and valid calendar scopes before reporting connected status or permitting synchronization.
- **UI Optimistic State Rollback**: Settings UI gracefully reverts toggles and presents actionable alerts if updates fail.
- **Dedicated Calendar Selector**: Clear differentiation between Primary Calendar (`primary`) and secondary calendar generation (`create_sage_calendar`).

## 5. Concurrency-Safe Refresh & Resilient Disconnection
- **CAS Token Refresh**: Google OAuth token refreshes use Compare-And-Swap (CAS) matching prior access token, refresh token, and expiration timestamp. If another request refreshes concurrently, the winning row is reloaded without error.
- **Comprehensive Disconnect**: Disconnect inspects all Google account rows (`findMany`), revokes tokens with Google's revocation endpoint, handles corrupt or invalid tokens safely without trapping the user, and returns actionable `revocationWarning` guidance if network revocation is incomplete.

## 6. Cryptographic Key Separation & Domain-Separated Derivation
- **No Secret Overloading**: Decoupled `NEXTAUTH_SECRET`, `PALATE_ENCRYPTION_SECRET`, `PALATE_RATE_LIMIT_SECRET`, and `CRON_SECRET`.
- **Domain Separation**: Derived distinct cryptographic keys for OAuth tokens (`palate:google-oauth-token:v1`), UserConfig Gemini API keys (`palate:gemini-api-key:v1`), and OAuth state (`palate:oauth-state:v1`).
- **Fail-Closed Production Behavior**: Token decryption strictly fails closed in production without `PALATE_ENCRYPTION_SECRET` (no fallback to session secrets for OAuth envelopes).
- **Pairwise Verification**: Startup integrity check verifies all production secrets are pairwise distinct without leaking secret values.

## 7. Atomic CAS Migrations & Reproducible Admin CLI
- **Reproducible CLI**: Standalone administrative entrypoints exposed via pinned npm scripts (`npm run admin:userconfig:*`, `npm run admin:tokens:*`, `npm run admin:users:*`).
- **UserConfig CAS Migration**: Migrates legacy Gemini keys to `PALATE_ENCRYPTION_SECRET` using CAS predicates and pre-commit in-memory roundtrip validation.
- **Google Token Classification**: Classifies historical tokens into `primaryKeyEncrypted`, `plaintextLegacy`, `malformed`, and `unreadable`.

## 8. Jellyfin Session Provenance & Legacy Account Protection
- **Session Provenance**: NextAuth JWT and session callbacks stamp `authProvider: "jellyfin"` and `jellyfinAuthenticated: true`. Legacy Google session tokens lacking this marker are rejected at middleware and API boundaries without rotating production `NEXTAUTH_SECRET`.
- **Pre-Cutover Block**: Documented that production deployment is blocked until the 4 existing Google-era accounts are pre-linked or individually reviewed.
- **No Auto-Merging**: Forbidden automatic merging of accounts by email or username. Delivered idempotent CLI pre-linking utility (`npm run admin:users:pre-link`).

## 9. Real PostgreSQL Kitchen Verification
- **PostgreSQL Test Suite**: Implemented `tests/integration/kitchen.db.test.ts` running against a real PostgreSQL instance (`palate_test`) covering all 14 operational scenarios.
- **Auto-Provisioning CAS**: Prevents duplicate orphan households under concurrent logins.
- **Atomic Invites**: Invites generation atomically expires previous active invites (`$transaction`); redemption is race-proof.

## 10. Lint, Static Architecture & Diagnostics Integrity
- **Zero Global Downgrades**: Preserved strict linting standards and eliminated unused variable warnings in production components.
- **Static Architecture Verification**: Implemented `tests/static/serverOnlyImports.test.ts` ensuring client components never import `server-only`.
- **Clean Git Diffs**: Verified clean whitespace and zero trailing whitespace issues via `git diff --check`.
