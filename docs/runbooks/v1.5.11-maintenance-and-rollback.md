# Palate v1.5.11 Maintenance-Window & Rollback Runbook

**Release Version:** `1.5.11`  
**Target Environment:** Production (`venus.whatbox.ca` / `/mnt/mpathe/betheenvy/Palate`)  
**Estimated Maintenance Duration:** < 2 minutes service downtime (pre-staged build & test)  
**Traffic Window:** Off-peak recommended (e.g. 02:00–04:00 UTC)

---

## 1. Architectural Safety Principles & Invariants

1. **Zero-Downtime Pre-Staging**: Never stop the running production service to perform dependency installation, test execution, or compilation. All building, testing, and preflight checks occur in a separate staging worktree.
2. **Atomic Data Protection**: Take a secure, validated database dump with strict permissions (`umask 077`) before touching database schema or running migrations.
3. **Mandatory Identity Pre-Linking**: No historical Google user is migrated without an explicit, operator-verified Jellyfin Server ID and User ID. The Google OAuth provider is strictly disabled for login.
4. **Fail-Closed Secret Separation**: Production requires 4 distinct secrets (`NEXTAUTH_SECRET`, `PALATE_ENCRYPTION_SECRET`, `PALATE_RATE_LIMIT_SECRET`, `CRON_SECRET`), each >= 32 characters, pairwise distinct. Decryption fails closed if `PALATE_ENCRYPTION_SECRET` is absent.
5. **No Secrets in Process Arguments or Crontabs**: All secrets reside in protected `.env.local` or environment files with mode `0600`.

## 2. Phase A: Secure Database Backup & Verification (Pre-Window)

Execute on `venus.whatbox.ca` before touching any application code.

### 1. Create Dedicated Backup Directory with Restrictive Permissions
```bash
# Enforce owner-only read/write (0700) for all backup artifacts
install -d -m 0700 /mnt/mpathe/betheenvy/backups/palate
cd /mnt/mpathe/betheenvy/backups/palate
umask 077
```

### 2. Export Full Database Dump
```bash
DUMP_FILE="/mnt/mpathe/betheenvy/backups/palate/palate_backup_v1.5.11_$(date +%Y%m%d_%H%M%S).dump"

# Dump custom archive format
pg_dump "$DATABASE_URL" -F c -b -v -f "$DUMP_FILE"
chmod 0600 "$DUMP_FILE"
```

### 3. Compute Checksum & Validate Dump Integrity
```bash
# Generate SHA256 checksum
sha256sum "$DUMP_FILE" > "${DUMP_FILE}.sha256"

# Verify dump file is non-empty and readable by pg_restore
pg_restore --list "$DUMP_FILE" > /dev/null
echo "Database dump successfully validated: $DUMP_FILE"
```

## 3. Phase B: Staging, Pre-Building & Automated Verification (Live Service Still Running)

The running Palate production instance remains active and serving traffic during this phase.

### 1. Prepare Staging Worktree for v1.5.11

### 5. Client Bundle Secret Scan

## 4. Phase C: Identity Pre-Linking & Preflight Dry-Runs (Live Service Still Running)

Execute preflight commands from the verified staging tree (`$STAGING_DIR`) against the live production database:

### 1. Verify Jellyfin Server Identity
Query the internal Jellyfin server to obtain the exact, durable `ServerId`:
```bash
JELLYFIN_SERVER_ID=$(curl -s "http://localhost:8096/System/Info/Public" | jq -r .Id)
echo "Verified Jellyfin ServerId: $JELLYFIN_SERVER_ID"
```

### 2. Inspect Historical Google Accounts
```bash
npm run admin:users:count-google
npm run admin:users:collision-report
```

### 3. Pre-Link Google-Era Accounts (Required for Unlinked Accounts)
For every Google-era user, link their account to their Jellyfin identity:
```bash
npm run admin:users:pre-link -- \
  --confirmed \
  --palate-user-id="<PALATE_USER_ID>" \
  --jellyfin-server-id="$JELLYFIN_SERVER_ID" \
  --jellyfin-user-id="<JELLYFIN_USER_ID>" \
  --jellyfin-username="<JELLYFIN_USERNAME>"
```
Verify zero unlinked Google users remain:
```bash
npm run admin:users:count-google
```

### 4. Run Migration Preflight Dry-Runs
```bash
npm run admin:userconfig:dry-run
npm run admin:tokens:dry-run
```
*Requirement:* Both dry-run executions must report `errors: 0`.

## 5. Phase D: Cutover Window (< 2 Minutes)

Now that the release build is pre-compiled and preflight checks have passed, proceed with service cutover.

### 1. Stop Active Palate Service
```bash
screen -X -S palate quit || true
```

### 2. Sync Production Directory to Staged v1.5.11 Release
```bash
cd /mnt/mpathe/betheenvy/Palate
git pull origin master
npm ci
npx prisma generate
```

### 3. Apply Schema Changes
```bash
npx prisma db push
```

### 4. Execute Live Data Migrations with Mandatory --confirmed
```bash
# 1. Migrate UserConfig Gemini keys to domain-separated key
npm run admin:userconfig:migrate -- --confirmed

# 2. Migrate Google OAuth tokens to AES-256-GCM encryption
npm run admin:tokens:migrate -- --confirmed
```
*Verification of Output Fields:*
- UserConfig migration must report: `errors: 0`, `casSkipped: 0`.
- Token migration must report: `errors: 0`, `casSkipped: 0`, `unreadableSkipped: 0`, `malformedSkipped: 0`.
Both commands will exit with code 1 if any unresolved records exist.

### 5. Post-Migration Verification Inspection
Re-run read-only inspection and verify zero remaining unmigrated records:
```bash
npm run admin:userconfig:inspect
npm run admin:tokens:inspect
```
*Invariants:*
- `userconfig:inspect`: `needsMigration: 0`, `unreadable: 0`, `incompleteTriples: 0`.
- `tokens:inspect`: `plaintextLegacy: 0`, `unreadableOrCorrupt: 0`.

### 6. Swap Pre-Built Assets & Launch Service
```bash
# Copy pre-compiled production build from staging tree
cp -r "$STAGING_DIR/.next" /mnt/mpathe/betheenvy/Palate/

# Launch production service daemon in screen session
screen -dmS palate bash -c "/home/betheenvy/start_palate.sh"
```

### 7. Post-Cutover Verification
```bash
# 1. Health check
sleep 5
curl -f http://localhost:28014/login

# 2. Automated curation test
. ~/.palate_cron.env
curl -X POST -H "Authorization: Bearer $CRON_SECRET" http://localhost:28014/api/curate
```

## 6. Emergency Rollback Procedure

If a critical failure occurs during migration or startup:

1. **Immediately Stop Service**:
   ```bash
   screen -X -S palate quit || true
   ```

2. **Restore Pre-Maintenance Database Dump**:
   ```bash
   # Re-verify checksum before restore
   cd /mnt/mpathe/betheenvy/backups/palate
   sha256sum -c "${DUMP_FILE}.sha256"

   # Restore database from validated dump
   pg_restore --clean --if-exists -d "$DATABASE_URL" "$DUMP_FILE"
   ```

3. **Revert Application Working Tree**:
   ```bash
   cd /mnt/mpathe/betheenvy/Palate
   git checkout HEAD~1
   npm ci
   npx prisma generate
   npm run build
   ```

4. **Restart Previous Release**:
   ```bash
   screen -dmS palate bash -c "/home/betheenvy/start_palate.sh"
   curl -f http://localhost:28014/login
   ```
